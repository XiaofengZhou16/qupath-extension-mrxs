# 项目 IF 批处理简明说明

适用于已发布的 `v0.5.0-snapshot-20261114` 预览版，安装和入口见 [首页](../README.md)。固定交付时以包内 JAR 校验值为准，不能仅凭 `0.5.0-SNAPSHOT` 判断是同一版本。

## 开始前

1. 打开 QuPath 项目。为每张切片的目标组织区域绘制面积 ROI，给 ROI 命名，并保存该切片的图像数据。批处理读取磁盘上已保存的标注，未保存的当前修改不会自动加入。
2. 打开其中一张多通道 MRXS，在 `Multiplex IF analysis` 设置参与统计的通道、阳性阈值、分析层级和 AI 输入通道。选择 InstanSeg、可信模型及设备；确认模型来源。
3. 需要报告配图时先设置当前显示颜色与亮度。显示配置仅用于图像呈现，不代替测量阈值。所有所选切片须具有相同的通道名和顺序；抗体对应仍需根据实验记录核对。

## 选择与运行

点击 `Project AI batch… / 项目 AI 批处理…`，再点击“读取已保存 ROI”。列表显示切片名、ROI 名和包围框尺寸；按 Command/Shift 多选需要的区域。检查区域数量和尺寸，避免把命名的小标注当作组织区域。IF 复核组/细胞标注不会自动进入列表；没有命名 ROI 的切片不会转为整片分析。

点击“运行所选 ROI”，选择输出父目录。程序自动新建 `if-batch-UUID` 文件夹，每项结果写入独立 `attempt-UUID`。任务顺序执行，同张切片复用队列读取器，跨切片时关闭；不会向项目自动插入 AI 检测对象，也不会覆盖原分析。

“队列结束”不保证所有任务成功。查看窗口的完成数/计划数及逐项状态；错误可能来自通道不匹配、ROI 边界、模型或来源变化。失败结果不可解释为阴性或零细胞。

## 取消与恢复

点击“取消”后等待控件恢复。当前底层推理需要安全结束，后续 ROI 不再启动；不存在“立刻停止”的保证。运行时关闭批处理窗口也会请求取消，并等待后台结束。

恢复时重新打开批处理窗口，选择“恢复已保存批次”，指定原 `if-batch-UUID` 目录。使用原插件版本，并在分析面板选中相同且已确认可信的模型目录。恢复使用保存清单内的分析参数，不用当前面板的新阈值替换它们。

模型内容、源文件抽样指纹、ROI/参数、插件或模型运行设置改变时会拒绝续跑。需要改变方案时创建新批次，保留旧目录；不要编辑任务指纹来绕过检查。源指纹只是头/中/尾抽样加文件元数据，不是完整切片内容认证。

已完成项会重新核对身份和全部输出文件哈希；失败、取消或中断项重试时使用新目录。旧尝试不删除。仍带 `INCOMPLETE` 的结果不能使用。

## 汇总与人工复核

点击“导出批次结果”，选择原批次目录。默认 Excel，可选 Word；报告保存到新的 `batch-report-UUID` 子目录，不覆盖已有报告。

先读 `README.txt` 和 `batch-status.json`：它们列出每个计划 ROI 的状态和实际纳入数。`office/results.xlsx` 包含各 ROI 的组合统计；未完成项不会伪造为零。最新结果损坏时不会自动用旧结果替代。多个 ROI 不作为独立动物重复，也不会自动汇总成组间检验。

需要查看细胞、排除原因或人工修正时，在原有分析历史窗口选择具体的 `attempt-UUID` 结果目录，使用定位/复核副本流程。修正后的重测是新分析，当前批次汇总不会自动将它替换到旧任务中；应在历史报告中明确选择修正后的版本。

## 保留哪些文件

保留完整批次目录：`batch-plan.json` 是任务及设置，`queue.json` 是尝试状态，各 `attempt-UUID` 保存结果与校验，`batch-session-UUID.jsonl` 保存分阶段耗时和资源采样。报告是另存快照；生成后再恢复批次不会自动更新已导出的报告。

工作线程数与模型 predictor 数不同。双 predictor 的小负载对照有加速观察，但目前仅在独立测试启动配置中验证，不应仅凭工作线程下拉框认定启用了该配置。阶段堆用量不是峰值 RSS 或 GPU 用量。
